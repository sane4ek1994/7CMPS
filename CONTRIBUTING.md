# Как добавить материал в DevOps Campus

Спасибо, что делитесь! Любой материал добавляется через pull request (PR). После
проверки и слияния в `main` сайт пересоберётся сам, и материал появится на нём.

## Что можно добавить

| Что                                           | Куда                                    | `kind`    |
| --------------------------------------------- | --------------------------------------- | --------- |
| Конспект занятия или темы                     | `cohorts/<поток>/` или `topics/<тема>/` | `notes`   |
| Презентация (текстом в Markdown, можно с PDF) | `cohorts/<поток>/`                      | `slides`  |
| Пример документации: runbook, README, ADR     | `cohorts/<поток>/` или `topics/<тема>/` | `docs`    |
| Практический проект                           | `projects/`                             | `project` |

- **`cohorts/07/`** — материалы 7-го потока («7 Кампус»). Пишите сюда, если материал
  про занятие вашего потока.
- **`topics/<тема>/`** — общие материалы, полезные любому потоку. Темы сейчас:
  `linux`, `docker`, `ci-cd`, `kubernetes`, `terraform`.
- **`projects/`** — описание вашего проекта со ссылкой на репозиторий.

## Способ 1: прямо в браузере (без установки)

1. Откройте нужную папку на GitHub, например `cohorts/07`.
2. Нажмите **Add file → Create new file**. GitHub сам предложит сделать форк.
3. Назовите файл по правилам ниже, например `docker-volumes.md`.
4. Вставьте шаблон из раздела «Шаблон материала» и напишите текст.
   Вкладка **Preview** покажет, как он выглядит.
5. Нажмите **Commit changes… → Propose changes**, затем **Create pull request**.
6. Заполните чек-лист в описании PR. Если проверки упадут, откройте их лог: там
   написано, какой файл и какое поле исправить.

## Способ 2: локально

```bash
git clone https://github.com/<ваш-логин>/7CMPS.git
cd 7CMPS
npm ci
git switch -c add-docker-volumes
# создайте файл, затем
npm run dev        # посмотреть результат на http://localhost:3000
npm run lint:md    # проверить оформление Markdown
npm run build      # убедиться, что сборка проходит
git add . && git commit -m "Конспект: Docker, тома и сети"
git push -u origin add-docker-volumes
```

Затем откройте pull request в основной репозиторий.

## Имя файла

- Только латинские буквы в нижнем регистре, цифры, `-` и `_`: `linux-permissions.md`.
- Кириллица, пробелы и заглавные буквы в имени не допускаются: имя станет адресом страницы.
- Адрес страницы повторяет путь: `cohorts/07/linux-permissions.md` → `/cohorts/07/linux-permissions/`.
- Не называйте материал `README.md` в корне папки: такой файл описывает саму папку.

## Шаблон материала

```markdown
---
title: "Linux: права доступа без магии"
author: your-github-login
topic: linux
cohort: "07"
date: 2026-10-12
kind: notes
tags: [linux, chmod, пользователи]
---

Первый абзац — короткое описание материала. Он показывается в списке файлов.

## Первый раздел

Текст, списки, таблицы и блоки кода с указанием языка: bash, yaml, dockerfile и другие.
```

### Поля frontmatter

| Поле          | Обязательно       | Что писать                                                                                       |
| ------------- | ----------------- | ------------------------------------------------------------------------------------------------ |
| `title`       | да                | заголовок материала; в кавычках, если внутри есть двоеточие                                      |
| `author`      | да                | ваш логин на GitHub (без `@`); можно перечислить через запятую                                   |
| `date`        | да                | дата в формате `ГГГГ-ММ-ДД`                                                                      |
| `topic`       | да для `cohorts/` | одна из тем: `linux`, `docker`, `ci-cd`, `kubernetes`, `terraform`; в `topics/` берётся из папки |
| `cohort`      | нет               | номер потока в кавычках: `"07"`; в `cohorts/` берётся из папки                                   |
| `kind`        | нет               | `notes` (по умолчанию), `slides`, `docs`, `project`                                              |
| `tags`        | нет               | список тегов: `[docker, volumes]`                                                                |
| `description` | нет               | своё описание для списка вместо первого абзаца                                                   |
| `repo`        | нет               | ссылка на репозиторий (для проектов)                                                             |
| `demo`        | нет               | ссылка на демо (для проектов)                                                                    |

Если поле заполнено неверно, сборка упадёт с понятным сообщением, например:

```text
cohorts/07/my-notes.md: поле date должно быть в формате ГГГГ-ММ-ДД
```

### Заголовки

Заголовок материала берётся из `title`, поэтому в тексте начинайте с `##`, а не с `#`.

### Картинки, схемы и PDF

Положите файл рядом с материалом (например, в `cohorts/07/assets/`) и сошлитесь на него
относительным путём:

```markdown
![Схема сети](./assets/network.png)
[Слайды в PDF](./assets/docker-slides.pdf)
```

Ссылки на другие материалы тоже пишите относительными путями к `.md`-файлам:
`[Права доступа](../../topics/linux/permissions.md)`. Такие ссылки работают и на GitHub,
и на сайте.

## Шаблон проекта

Файл кладётся в `projects/`, например `projects/k8s-home-lab.md`:

```markdown
---
title: Домашний кластер Kubernetes на трёх Raspberry Pi
author: your-github-login
topic: kubernetes
cohort: "07"
date: 2026-11-20
kind: project
tags: [kubernetes, k3s, homelab]
repo: https://github.com/your-github-login/k8s-home-lab
demo: https://your-demo.example.org
---

Одним абзацем: какую задачу решает проект.

## Что сделано

## Стек

## Что было сложно и чему научился

## Что можно улучшить
```

## Правила

- **Только свой текст.** Не копируйте платные курсы, чужие статьи и слайды. Короткие
  цитаты допустимы со ссылкой на источник.
- **Лицензия.** Материалы публикуются под [CC BY-SA 4.0](LICENSE-CONTENT.md): их можно
  переиспользовать с указанием автора. Отправляя PR, вы соглашаетесь с этим.
- **Без секретов и личных данных.** Никаких токенов, паролей, приватных ключей, IP-адресов
  рабочих серверов, телефонов и e-mail. В `author` указывайте только логин GitHub.
- **Без чужих логотипов** в картинках и схемах.
- **Один PR — одна тема.** Так его проще проверить.

## Новая тема или новый поток

- **Тема:** создайте папку `topics/<ключ>/` и файл `README.md` в ней:

  ```markdown
  ---
  title: Ansible
  icon: terminal
  description: Управление конфигурацией серверов.
  ---

  Пара предложений о теме.
  ```

  Доступные иконки: `terminal`, `container`, `cycle`, `nodes`, `blocks`, `folder`,
  `docs`, `notes`, `globe`.

- **Поток:** создайте папку `cohorts/<номер>/` (например, `cohorts/08/`) с `README.md`,
  где в `title` указано название потока. Папка сама появится на рабочем столе.

## Ошибки и идеи

Нашли ошибку в материале или на сайте, хотите предложить тему? Откройте
[issue](https://github.com/sane4ek1994/7CMPS/issues/new/choose): там есть готовые шаблоны.
