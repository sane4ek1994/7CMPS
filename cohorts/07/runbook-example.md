Шаблон runbook'а, то есть инструкции для дежурного, которую можно выполнить по шагам
без автора сервиса рядом. Сервис вымышленный, структуру можно копировать в свои проекты.

## Карточка сервиса

| Поле | Значение |
| --- | --- |
| Сервис | `notes-api`: учебный REST API заметок |
| Владелец | команда «Кампус», канал «Помогите разобраться» |
| Окружения | `staging`, `production` |
| Как деплоится | GitHub Actions, workflow `deploy.yml` |
| Где логи | `journalctl -u notes-api` на хосте приложения |

## Перед деплоем

- [ ] Сборка в `main` зелёная.
- [ ] Миграции базы обратно совместимы (старая версия сервиса работает с новой схемой).
- [ ] В `CHANGELOG.md` описано, что меняется.

## Деплой

1. Откройте вкладку **Actions**, выберите workflow **deploy** и нажмите **Run workflow**.
2. Выберите окружение `staging` и дождитесь зелёного статуса.
3. Проверьте здоровье сервиса:

   ```bash
   curl -fsS https://staging.example.com/healthz
   ```

4. Если проверка прошла, повторите шаги 1–3 для `production`.

## Откат

```bash
# на хосте приложения: вернуть предыдущий релиз
sudo ln -sfn /opt/notes-api/releases/previous /opt/notes-api/current
sudo systemctl restart notes-api
```

После отката обязательно напишите в канал, что случилось, и заведите issue.

## Частые проблемы

| Симптом | Вероятная причина | Что сделать |
| --- | --- | --- |
| `healthz` отвечает 502 | сервис не стартовал | `journalctl -u notes-api -n 50` |
| деплой висит на шаге миграций | блокировка таблицы | проверить долгие транзакции в БД |
| в логах `permission denied` | у пользователя сервиса нет прав на каталог | `ls -la /opt/notes-api` |
